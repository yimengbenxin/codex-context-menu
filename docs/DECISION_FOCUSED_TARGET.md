# 多对话焦点定位决策

## EXTEND：修复目标身份的源头，不修改预算或模型执行链

业务目标：多个对话同时运行时，识别用户所在窗口的对话，而不是最新输出或最新订阅的对话；不修改聊天历史或官方文件。

已核对调用链：识别按钮 → AppDelegate → IPC 订阅数量门禁 → ContextTarget → 会话元数据 → 配置模型。当前门禁要求恰好一个订阅；订阅不是窗口焦点，因此多个订阅时失败，且不能把最近订阅当焦点。

比较方案：IPC 源头目前没有可用的焦点广播；直接扩大订阅门禁会猜错目标；按标题模糊匹配或最近活动选择会在重名及后台输出时误判。选择一个只读 macOS 薄适配，读取 Codex 记忆的焦点窗口中应用 WebArea 的标题，用官方本地 SQLite 的有效显示名称精确查询唯一 ID，再复用原有 ContextTarget 校验会话 ID、桌面来源及项目目录。

焦点采样在定位前后复核进程、窗口和标题；不遍历 WebArea 的聊天子树，不改 SQLite，不维护第二套对话索引或持久焦点状态。实测发现即使只有一个订阅也可能指向后台对话，因此缺少辅助功能权限时不再用订阅充当焦点，明确提示授权或使用深度链接；重名、焦点变化或非对话页不猜测，保留旧目标但阻止保存。

本单元的协议/平台适配与既有深度链接解析合并计量，控制在 200 行内。预算状态、下一轮加载及权限恢复继续由原权威模块负责。

验证：唯一/重复/重命名/归档标题、数据库只读、焦点变化、权限缺失、旧目标阻止保存；原配置、压缩策略、历史和生命周期回归；本机多个订阅下真实识别按钮以及标题和 ID 对照。没有实测的场景不宣称通过。
