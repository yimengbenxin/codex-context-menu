# Complete Codex usage surface

Decision: EXTEND the existing CodexBar-backed data contract and REUSE the incumbent SwiftUI window, status menu, polling and local-history sandbox. Do not add another log parser, pricing catalog, OAuth implementation, credential registry or background scheduler.

The current consumer drops most fields already emitted by the pinned MIT-licensed CodexBar CLI. Expose its full Codex local-token metrics, daily/model/project breakdowns, cost provenance/coverage, remote quota windows and other OAuth-returned account metrics. Add period selection and a status-menu usage entry; ordinary launch and double-click remain context-first. Active-thread numbers come from the existing TokenLogMonitor and are labeled as monitored-thread snapshots, not all-device/account billing.

Derived cache hit rate is cached input / total input, never cached tokens / input-plus-output. Reasoning is an output subset and must not be added to total again. Unknown or invalid counters and missing prices stay unknown. API list-price estimates are not subscription charges. Local snapshots and official account snapshots have separate timestamps, errors and refresh schedules. No browser-cookie/dashboard fallback, credential switching or additional-provider integration is part of this change.

Preserve the 0.6.12 statistics filesystem/network boundary and Codex configuration/history. Validate producer JSON, consumers, missing/partial data, period-switch races, menu routing, packaged resources, native history statistics and the visible macOS interface. Ship only verified supported capabilities, not a claim of complete CodexBar multi-provider parity.

The installed background and foreground launch paths previously created two companion processes and two polling owners. Fix the launch producer, not the statistics scheduler: the login item launches the app through macOS Launch Services, and subsequent opens reuse its normal reopen callback. No secondary singleton IPC, polling service or credential lock is added.

Verification: 76 Node, 49 Python and 50 Swift checks passed, including complete native payload decoding, request-versus-cumulative counters, cache denominator, unknown data, period-switch races, forced refresh and stale-error retention. The installed native CLI's month-to-date query returned the expected local dates and complete token fields. The real macOS interface displayed current-request and daily counters, cache hit ratios, account quota and Credits; its usage menu opened the complete dashboard, and the context page remained the default. A bounded visual pass fixed the persistent header, local date labels and partial-price warning. Repeated launch/open left one companion process. The official Codex process and protected configuration/runtime hashes were preserved. This is a Codex-only native-data integration, not the browser dashboard or all-provider/account-switching functionality of CodexBar.
