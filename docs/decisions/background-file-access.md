# Background file permission requests

Decision: EXTEND the existing local statistics boundary and REUSE explicit target selection.

The observed chain is UsageModel's periodic refresh -> UsageBackend -> bundled CodexBarCLI -> Git -> macOS Desktop-folder access checks attributed to CodexContextMenu. The previous sandbox denied network only, so statistics could inspect project locations despite needing only Codex history. Independently, context_config.status resolved every registered project's filesystem path while checking one selected project's trust, and opening settings automatically reloaded the last project.

Keep the existing token parser/statistics provider and context runtime. Restrict optional statistics discovery at its existing command boundary, remove unsolicited last-project loading, and compare registered trust paths without probing unrelated directories. Background launch must not open settings merely because the runtime is absent. Explicitly selecting a protected project can still require macOS consent; no permission database reset, Full Disk Access requirement, or official Codex binary change is part of this fix.

Alternatives compared: the pinned provider has no switch to disable project discovery. A source fork could add one at its canonical-project resolver, but would introduce a separately rebuilt and maintained CLI. Use the already-owned sandbox-exec boundary instead: the provider can read its required system/runtime files, Codex history, preferences and caches, but cannot read arbitrary project directories. Its existing inaccessible-project fallback retains raw project paths and daily/token totals. Worktree project grouping is not consumed by this app. There is no new parser or scheduler; network remains denied for local statistics. The quota command remains separate and follows the existing explicit preference.

Acceptance: restricted local statistics still return token totals; unrelated registered roots are not resolved; trust inheritance and explicit target configuration continue working; background launch stays background. Verify packaged resources and preserve main Codex process, configuration, and chat data. Logs showing an access check are not by themselves proof that a consent dialog was displayed on another Mac.

Local verification: 76 Node, 49 Python and 41 Swift tests passed. The native statistics fixture matches the original daily/totals output, including local-calendar dates, and handles incremental history while denying project metadata and symlink-based project reads. Packaged 0.6.12 was installed; official CLI/global configuration/thread settings hashes, the selected history prefix and main Codex process were preserved. During a 185-second observation, six periodic cost processes were seen, no Git descendants were observed, and no Desktop/Documents/Downloads TCC requests were attributed to the companion. This observation is bounded and does not establish consent behavior on an uninspected second Mac. The two existing companion launch modes both ran during observation; their separate lifecycle is outside this folder-access fix.
