# EXTEND：自适应逐级回退

端到端目标：成功自动压缩后的保留量连续两次低于相邻低档预算乘用户已有低阈值时，下一安全启动边界回退一级。最低档不回退，升档阈值和计次规则不变。默认比例仍来自 defaults.json，保存的用户阈值、档位保持权威，不增加独立回退输入项。

复用 CompactionObserver 现有压缩完成快照作为回退样本源，BudgetStore 作为唯一计数和档位持久化所有者，AdaptiveController 作为唯一加载边界。不得用本轮最后的模型输入、压缩前用量或累计消耗冒充压缩完成后保留量；缺少完成快照就中断回退计数。手动、失败、未知、达到回退线的样本打断连续性；升降后重置。多个压缩样本属于同一轮时最多改变一档；已计划但尚未加载新档后收到旧运行档的样本，不能继续跳档。新政策 revision 沿用现有第一档重置机制。

不新增轮询、日志解析器、数据库或目标调度器；只扩展现有纯业务反馈规则和观察器消费者合同。保留官方签名内核、项目配置和聊天记录。目标内部自动续跑仍受已有加载边界限制，不宣称活动轮原地热修改。

验证覆盖上下两条规则、严格小于边界、两档回退、异常打断、采集时序、同轮多压缩、下一轮加载、加载失败恢复、重启计数、并发存储、revision 和对话隔离。签名官方 CLI 金丝雀在隔离 HOME/CODEX_HOME 及本地响应服务验证升档后两次低保留回退、重启间计数保持、历史前缀与数据库完整性。完成隔离验收后才安装伴随组件，不重启主 Codex 或中断活动目标。

降档样本复用观察器已有的 thread/turn/item 哈希作为 ID，BudgetStore 保留最近已消费 ID，避免同一压缩在重复通知或跨进程重送时计两次。只记录数字、布尔值和事件哈希，不上传代码、聊天或凭据。

2026-10-01 源码隔离金丝雀通过：272K→485K，再两次低样本→272K；再升到872K，两次低样本→485K。两条回退路径都把第一次低样本保存后重启，第二次仍正确触发。新档位的窗口反馈分别为258400和460750；原项目配置、历史前缀与官方二进制保持。该验收是签名运行时配合本地合成响应，不是实际长任务稳定性、模型压缩质量或活动目标原地换档证明。

并发验收复现既有锁竞争：另一个写入者在竞争者 lstat 与 readFile 之间正常释放 writer.lock，读取抛 ENOENT 导致漏记一次反馈。于唯一状态所有者 BudgetStore 接受此正常释放并回到既有有界抢锁循环；不增加重试层、延长超时或吞掉其他错误。增加可确定复现的锁释放时序测试，并补跑跨进程竞争检查。
