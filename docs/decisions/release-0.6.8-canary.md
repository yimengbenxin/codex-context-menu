# EXTEND：0.6.8隔离金丝雀与发布

复用现有官方原生协议夹具，不另建模拟内核或第二套统计算法。同一签名内核在独立HOME/CODEX_HOME和localhost合成响应中产生压缩通知，经发布包内观察器、SQLite所有者、配置预览接口读取真实写入的数字记录。

验收覆盖两种272K/95%场景，每组11次自动成功压缩，跨冷重启、历史前缀不变、数据库完整性和数值隐私白名单；270005未越预算、280005越预算时分别保留95%及建议92%。用量是受控合成值，不冒充真实服务端质量或概率。测试只读主配置与官方程序并比对摘要，不触碰主应用生命周期。

包校验依据本次版本而非旧版本，验证资源与源代码一致，并对解包资源重跑同一原生金丝雀。CI增加观察器与统计模块测试。发布从干净提交产生ZIP/DMG、远端下载比对SHA256。发布仍标为实验性试用版；新增运行组件须由用户完整重启一次加载，验收不自动重启主Codex。

本机云同步目录曾导致Swift对象文件构建中被修改。统一测试入口使用新建临时构建目录，不改业务源码规避编译错误；可选打包缓存必须与仓库Package.swift及全部Sources一致，否则拒绝构建。隐私扫描中的someone@example.com是公开测试夹具，仅将该精确示例地址加入本次扫描白名单，不放宽其他地址或凭据检查。

解包金丝雀发现Node入口识别比较了词法路径与规范路径，macOS的/var与/private/var别名导致预览正常退出却无JSON。在policy模块自身统一用真实路径判断入口，并加入符号链接回归；不在消费者猜测空输出或增加重试。

首轮CI发现压缩设置单元夹具缺少运行时发现边界隔离，runner没有官方应用时3项报错。修正仅测试中的发现/签名桩，政策算法仍使用仓库真实Node模块；本机用明确不存在的官方应用路径复测通过，生产签名校验不变，原生金丝雀仍使用实际官方程序。
