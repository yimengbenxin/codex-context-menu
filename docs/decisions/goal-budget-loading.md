# EXTEND：统一对话启动入口的预算加载

目标：对话级自适应覆盖项目固定预算，并在启动或恢复目标任务前从最低档加载，不修改项目设置、聊天历史或官方内核。

确认的调用链：设置保存于 thread_settings.py；AdaptiveController.context 是唯一预算解析入口；before 原先只在 turn/start 卸载并重新加载预算。2026-10-01 本机目标对话先 thread/resume，随后保存自适应，再 thread/goal/set 启动；不存在 turn/start，因而仍使用此前 485000 的配置。后续 turn/steer 是向活动任务追加输入，不是空闲轮次。

方案比较：删除项目固定配置会影响其他对话；新增轮询控制器会重复状态所有权并与活动任务竞争；修改官方内核破坏签名接入。选择复用既有空闲边界加载流程，覆盖 thread/goal/set 的活动目标入口和 thread/queue/start，保留活动任务保护和失败恢复。活动任务不能把尚未加载的预算当成已应用的反馈上下文。

验证：单元测试覆盖目标入口、队列入口、非活动目标更新、活动任务不卸载、不错误记入新档反馈、继承固定项目预算及恢复失败。签名官方 CLI 与本地合成响应复现已加载 485K 后保存自适应，再启动目标，检查真实 tokenUsage 窗口为最低档；同时核对历史前缀、项目文件和数据库完整性。不把隔离验收冒充现有活动主线程已经生效。

2026-10-01 验收：现有安装运行同一新增金丝雀，失败于窗口仍为 460750；修复源码与 0.6.10 本地候选安装包分别通过，恢复既有暂停目标时窗口为 258400，目标内容及预算保持、历史前缀保持、项目配置不变、主全局配置及官方二进制哈希不变。37 项 Node、44 项 Python、40 项 Swift 检查通过。原生验证使用本地合成响应，不宣称长对话模型质量或活动任务原地热更新已通过。

剩余运行边界：thread/goal/set(active) 与 thread/queue/start 现在复用空闲加载入口。活动目标的 turn/steer 或内核内部自动续轮不能冒充此入口；官方运行中 settings 接口没有上下文预算字段，thread/resume 会忽略活动实例的 config。新组件安装后，已运行控制器仍在内存中使用旧代码，需一次重新启动 Codex 才加载此次组件更新；之后空闲目标恢复无需重启。不会自动暂停或终止用户目标任务。
