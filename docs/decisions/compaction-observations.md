# EXTEND：本地压缩观测与建议

复用官方签名内核、现有通知流和下一轮设置控制器。不替换内核，不代理模型请求，不开启官方调试分析捕获（该入口只在调试构建可用），不读取聊天正文或账号凭据。

唯一数值来源为 `thread/tokenUsage/updated` 的最近报告值；以 `contextCompaction` 的开始、完成和回合结束事件关联压缩。它不是服务端压缩请求精确输入，界面必须称为“观测预算越线率”，不得声称真实精确概率。默认压缩触发线未由接口报告时不猜测为95%或90%；仅已确认的工具自定义触发线参与触发线比较和推荐，默认仍能观测是否超用户预算。

薄事件转换由独立观察器负责，不改预算/模型/推理强度、不拦截或等待正常对话。数字记录、去重、保留、分组和建议由一个本地SQLite业务模块拥有；多进程用数据库事务统一写入。界面与预览只消费其报告，不另写推荐算法。只写工具自己的数据库，最多保留10000条，权限0600。失败不阻断对话。

按项目、对话、模型、预算、触发百分比与作用域分组；手动、失败和未知用量独立显示，不算成未越线。超过触发线是正常触发，不能冒充超过用户预算。主指标比较最近报告总量与预算；触发线超过量另列，不视为失败。至少10条可测且触发线已确认的自动成功样本、覆盖率至少80%才给建议。只有出现预算越线才按触发线超过量P95从预算中预留空间；未越预算不下调。仍受已有模型安全线和99%上限约束；建议不自动应用，不能保证改变百分比后得到同样概率。

验证覆盖通知顺序、重复、缺失、失败、手动、多个对话、重启、并发写入、坏数据库和隐私白名单；再使用隔离官方后端验收实际记录与读取链路。主Codex不自动重启，测试不写入主聊天记录。
