# 自动压缩线

- 留空继承当前范围的默认配置，不写死官方默认百分比。
- 自定义仅接受 1–99 的整数。超过 90% 时，输入框下显示红色小字：“超过90%可能在单轮对话中越过压缩线，请留意上下文余量。”这只是提示，不做风险归因。
- 工具额外要求压缩线不超过官方模型目录中原始最大窗口的 90%。这是工具的安全余量，不是官方模型硬上限。保存时由 `adaptive/policy.mjs` 唯一计算并验证；输入不符合时，不写入配置。自适应升档或切换模型后，运行时再次限幅。

例如模型原始最大窗口为 872K：预算 272K 可以输入 99%，触发目标为 269.28K；预算 870K 时，95% 不允许保存，整数百分比最高为 90%，目标为 783K。若模型原始最大窗口只有 272K，272K 预算最高为 90%。原始上限缺失时只使用官方初始窗口，不猜测更大容量。

实现保留官方签名内核，通过下一轮恢复同一对话加载设置。自定义触发线使用官方 `body_after_prefix` 和完整可用窗口检查，并依据官方可用比例推导实际原始窗口覆盖。因此“用户请求预算”“原生窗口覆盖”“最近运行窗口”不是同一个数字；界面显示真实运行反馈，不伪造窗口。模型、推理强度和官方压缩模型不变。

检查线不是传输层逐 token 截断器。一次较大的用户输入、工具输出或模型输出仍可能越过检查线，99%也不意味着不会超出。此限制只限制配置目标，不保证每次请求都低于该目标。

## 本地压缩观测与推荐（0.6.8）

运行组件加载后，实时关联压缩开始/完成与用量通知，记录最近报告的压缩前输入、总量、压缩后总量、耗时与结果。只保存数字、模型及必要标识，不读取/保存聊天正文、代码或凭据，不上传；项目路径只保留哈希。最多保留10000条，在当前对话或项目、当前模型与已保存预算下统计，不同触发百分比和作用域分开显示。

“观测预算越线率” = 最近报告的总量超过用户预算的自动成功压缩次数 / 具有可比用量的自动成功压缩次数。超过触发线是正常触发，另列其超过量，不算成预算越线。手动、失败、未完成、缺失用量单独计数；未知不当作未越线。官方默认未报告精确触发线时不猜测，仍可比较已观测用量与原始预算，但不给触发线建议。这不是服务端压缩请求精确输入，也不是严格因果概率；回合中新增但尚未报告的tokens可能遗漏。

至少10条可测且触发线已确认的自动成功样本、覆盖率达到80%后，出现预算越线时：建议百分比 = 向下取整（（预算 − 触发线超过量P95）/ 预算 × 100），再限于当前百分比、模型安全线和99%上限。未出现预算越线时不因正常触发而下调。P95包括零值，预算越线均值只统计超预算样本。272K预算、95%触发线，10次中3次用量277K（超预算5K），其触发线超过量18.6K，会给出保守参考93%。建议不会自动修改设置；不能推断换成93%后越线率一定是多少，也不把超预算等同于服务端报出context-length错误。

界面展开“本地压缩观测与推荐”查看分组和最近记录，“刷新压缩统计”只更新报告，不覆盖未保存的设置。新安装不会倒填历史；首次更新运行组件仍需完整重启Codex一次，之后自动记录，无需重复重启。
